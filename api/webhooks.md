# وبهوک

وقتی وضعیت یک فاکتور عوض می‌شود، به `callback_url` که موقع ساختش دادید یک `POST` می‌زنیم.

## رویدادها

<div dir="rtl">

| رویداد | کِی |
|---|---|
| `invoice.paid` | واریز تشخیص داده و تسویه شد |
| `invoice.expired` | مهلت فاکتور تمام شد بدون پرداخت |
| `invoice.cancelled` | فاکتور لغو شد |

</div>

## بدنه

```json
{
  "event": "invoice.paid",
  "invoice_id": "inv_9fk2m4qx7t3p8wzy1a6b",
  "order_id": "ORD-1043",
  "amount_rial": 5990000,
  "payable_rial": 5993240,
  "fee_rial": 40000,
  "status": "paid",
  "is_test": false,
  "paid_at": "2026-08-17T13:58:02+00:00",
  "metadata": {"customer": "u_882"}
}
```

`metadata` همان چیزی است که موقع ساخت فاکتور فرستاده اید. فاکتوری که از یک **لینک ارزی** ساخته شده، یک کلید `fx` هم در آن دارد که میگوید بابت چه بوده و با چه نرخی قفل شده:

```json
"metadata": {
  "fx": {
    "id": "fx_7qm2xp9kd4ra8tb1yc0z",
    "key": "crypto:USDT",
    "label": "تتر (USDT)",
    "quantity": "2",
    "unit_rial": 2323320,
    "markup_bps": 150,
    "feed_at": "2026-09-22T06:29:27+00:00"
  }
}
```

<div dir="rtl">

| کلید | یعنی |
|---|---|
| `id` | شناسه لینک ارزی؛ آدرس صفحه خریدار `/fx/{id}` است |
| `key` | دارایی به زبان API قیمت: `crypto:USDT` یا `gold:سکه ربع` |
| `quantity` | تعداد واحد، به صورت رشته تا اعشار رمز ارز گم نشود |
| `unit_rial` | نرخ هر واحد که قفل شد، با درصد فروشنده، به ریال |
| `markup_bps` | درصد فروشنده روی نرخ، در صدم درصد؛ `150` یعنی ۱٫۵ درصد |
| `feed_at` | زمان آخرین آپدیت API قیمت که نرخ از آن آمده |

</div>

## هدرها

<div dir="rtl">

| هدر | محتوا |
|---|---|
| `X-Event` | نام رویداد، همان که در بدنه است |
| `X-Delivery-Id` | شناسه‌ی یکتای این تلاش تحویل |
| `X-Timestamp` | زمان ارسال، ثانیه‌ی یونیکس |
| `X-Signature` | امضای HMAC — پایین |

</div>

## راستی‌آزمایی امضا

هرکسی می‌تواند به آدرس وبهوک شما درخواست بزند. **امضا را چک کنید، وگرنه یک غریبه می‌تواند سفارش تحویل‌نشده را «پرداخت‌شده» جا بزند.**

امضا `HMAC-SHA256` است، با کلید مخفی وبهوک فروشگاه شما (از پنل: تنظیمات ← وبهوک)، روی **بایت‌های خام بدنه** — نه روی JSON دوباره سریالایزشده. اگر بدنه را پارس و دوباره تبدیل کنید، امضا نمی‌خواند.

```php
<?php
$raw    = file_get_contents('php://input');
$sent   = $_SERVER['HTTP_X_SIGNATURE'] ?? '';
$mine   = hash_hmac('sha256', $raw, ABANGATE_WEBHOOK_SECRET);

if (!hash_equals($mine, $sent)) {
    http_response_code(401);
    exit;
}

$event = json_decode($raw, true);
```

```python
import hmac, hashlib

def valid(raw: bytes, sent: str, secret: str) -> bool:
    mine = hmac.new(secret.encode(), raw, hashlib.sha256).hexdigest()
    return hmac.compare_digest(mine, sent)
```

```js
import { createHmac, timingSafeEqual } from "node:crypto";

function valid(raw, sent, secret) {
  const mine = createHmac("sha256", secret).update(raw).digest("hex");
  const a = Buffer.from(mine), b = Buffer.from(sent);
  return a.length === b.length && timingSafeEqual(a, b);
}
```

> [!WARNING]
> برای مقایسه از `hash_equals` / `compare_digest` / `timingSafeEqual` استفاده کنید، نه `==`. مقایسه‌ی معمولی رشته به‌محض اولین کاراکتر متفاوت برمی‌گردد و همین تفاوت زمانی، حرف‌به‌حرف، امضا را قابل حدس‌زدن می‌کند.

## پاسخی که باید بدهید

هر کد `2xx` یعنی «رسید». هر چیز دیگری تلاش مجدد را راه می‌اندازد.

سریع جواب بدهید و کار سنگین را به صف بسپارید — اگر پاسخ دیر بیاید تحویل ناموفق حساب می‌شود، حتی اگر کار شما درست انجام شده باشد.

## تلاش مجدد

پنج بار، با فاصله‌های ۱۰ ثانیه، ۳۰ ثانیه، ۲ دقیقه، ۱۰ دقیقه و ۱ ساعت. بعد از آن تحویل «تمام‌شده» علامت می‌خورد و در پنل قابل دیدن است — تاریخچه‌ی همه‌ی تلاش‌ها با کد پاسخ، در **تنظیمات ← وبهوک**.

## یک رویداد، یک بار — ولی تکراری را هم تحمل کنید

هر (فاکتور، رویداد) فقط یک ردیف تحویل دارد، پس یک رویداد دوبار در صف نمی‌نشیند. با این حال ممکن است یک تحویل را دوبار ببینید: اگر پاسخ شما در راه گم شود، ما تلاش را ناموفق می‌بینیم و دوباره می‌فرستیم، در حالی که سرور شما کارش را کرده بود.

پس **کنترل‌کننده‌تان باید idempotent باشد**. ساده‌ترین راه: `invoice_id` را ذخیره کنید و اگر قبلاً دیده‌اید فقط `200` بدهید.

## اگر وبهوک اصلاً نرسید

اول پنل را ببینید — اگر تلاش‌ها آنجا با خطا ثبت شده‌اند، مشکل سمت شماست و کد پاسخ را می‌بینید. اگر هیچ تلاشی ثبت نشده، فاکتور هنوز تسویه نشده.

به‌عنوان تور نجات، `GET /api/v1/invoices/{id}` را روی سفارش‌های معلق بزنید — مثلاً یک بار در ساعت روی هر سفارشی که هنوز `pending` است. **جای وبهوک نگذاریدش**؛ فقط برای وقتی است که چیزی گم شده باشد.
